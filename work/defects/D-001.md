Title: `-o /dev/null` (and other non-regular output targets such as /dev/stdout) fails with exit 4

Steps:
    cd "$(mktemp -d)" && cp <repo>/docs/fixtures/scheduling-worked-example.yaml . \
      && uv run --project <repo> rt render scheduling-worked-example.yaml -o /dev/null; echo $?
    (same for `--plan /dev/null`, `-o /dev/stdout`)

Expected: exit 0. /dev/null is writable; RS 6.4 reserves exit 4 for an output that is not writable.
The atomic temp-file-and-rename of CLI-3 protects regular files from partial writes; it cannot apply
to a device (there is no directory entry to replace), so such targets should be written directly.
`rt render … -o /dev/null` is also the smoke check used by the team lead.

Actual:
    rt: error: cannot write /dev/null: Operation not permitted
    exit 4

Test: tests/cli/test_cli_general.py::test_output_to_dev_null
Note: a FIFO target (`-o some.fifo`) currently exits 0; check that it is written to, not replaced.

Re-check (same session, later build): `rt render … -o /dev/null` exits 0; test_output_to_dev_null passes.
Status set to verified.
